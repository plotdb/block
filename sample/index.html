@plotdb/block — Samples

A tour of core @plotdb/block features. See the source of each block file in sample/.

00 — Inline Block

A block can be defined directly in the page as a <template> tag, then registered via mgr.set() — no server round-trip needed. This is the fastest way to try out the API.

01 — Hello World

The most basic block: a plain HTML file loaded from a URL via the registry. The block's init(opt) receives opt.root (the mounted DOM node).

02 — Scoped Style

CSS inside a block is automatically scoped by @plotdb/csscope. The global .badge-global (grey) is unaffected by the block's blue .badge rule. Both block instances share the same scoped style without conflicts.

Outside block: global badge

03 — Interface

A block exposes a public API via interface(). mgr.from() resolves to { instance, interface }; the host calls methods on interface to control the block.

04 — Data

Pass a data object at cls.create({ data }). The block reads it from opt.data in init(). Three instances of the same class, each rendering different content.

05 — Extend (Inheritance & Plugs)

Blocks can extend other blocks. The base defines <plug name="…"> slots; children fill them with plug="…" attributes. You can also fill plugs from host HTML (no child block needed).

06 — i18n

Blocks bundle their own translations in pkg.i18n. HTML elements with t="key" are translated at attach time. Pass autoTransform:'i18n' to re-translate when the language changes.

07 — Headless Block

Call inst.attach() without a root to run a block in headless mode — init() runs but no DOM is inserted. Useful for pure-logic blocks (event buses, timers, services).

08 — Remote Block

The registry function maps a BID to a URL; the manager fetches the HTML, parses it, and caches the resulting class. Here clock is fetched from /sample/08-remote/index.html.
